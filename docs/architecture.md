## 3. 원칙: LLM은 어디에 쓰고 어디에 안 쓰나

1. **포지션 크기 → 리스크 → 주문 단계에는 LLM을 넣지 않는다.** 같은 입력에 같은 출력이 나와야 하고, 지연·비용·오류가 통제돼야 한다. LLM은 브로커를 직접 호출하지 않는다.
2. **LLM은 판단·해석·연구에 쓴다**: 시장 보고서, 뉴스 해석, 아이디어 발굴, 검증팀의 반박, 일지 요약, 코드 리뷰.
3. **LLM 판단 전략(lab 유형 `llm`)도 실험한다.** 단, LLM은 "관점"(방향·확신도·보유 기간)만 정해진 형식으로 내고, 그 관점을 주문으로 바꾸는 일은 일반 전략과 같은 결정론적 코드와 리스크팀이 맡는다. 검증 방식은 7절.
4. LLM이 만든 해석을 전략 입력으로 쓸 때는 반드시 **데이터로 저장**하고(날짜·입력·출력), 그 저장본만 사용한다.
5. 모든 인수인계는 **스키마가 정해진 파일/DB 레코드**로 한다 (day-trader-skill 방식). 역할 간 대화가 아니라 기록이 남는 계약이다.

## 7. LLM 판단 전략의 검증 트랙

**문제**: LLM은 학습 데이터로 이미 과거 시장의 결과를 알고 있다. 과거 날짜로 판단을 시키면 미래를 아는 상태에서 고르는 셈이라 일반 백테스트가 무의미하다.

**구조**
```
시점 t의 입력 스냅샷 ──▶ LLM ──▶ 관점 {방향, 확신도 0~1, 보유 기간, 근거}  ──▶ 결정론적 크기 산정 ──▶ 리스크 ──▶ 주문
(시세·지표·뉴스·국면)                     (JSON 스키마 고정, 전부 기록)
```

**검증 방법**
1. **앞으로 검증(주)**: 모의투자로 실시간 판단을 쌓는다. 이 기간 자체가 아웃오브샘플이다.
2. **지식 시점 이후 백테스트(보조)**: 모델 지식 시점 이후 데이터로만 백테스트한다 (예: 지식 시점이 2026년 6월인 모델은 2026년 7월 이후 데이터만). 시간이 지날수록 쓸 수 있는 구간이 길어진다. 모델이 바뀌면 그 모델의 지식 시점으로 다시 계산한다.
3. **일관성 검사**: 같은 입력으로 N번(예: 5회) 판단시켜 일치율을 잰다. 일치율이 낮으면 신호가 아니라 잡음이다.
4. **기준선 비교**: 같은 입력을 쓰는 단순 규칙(모멘텀, 매수 후 보유, 무작위)보다 나아야 한다. 못 이기면 LLM이 더하는 가치가 없다.

**통과 기준**: labs 공통 고정 기준(Sharpe, 거래 수, 비용 등)에 더해
- 앞으로 검증 최소 60거래일, 판단 30건 이상
- 일치율 70% 이상
- 기준선 대비 초과 성과
- **LLM 호출 비용을 거래 비용에 포함**

**버전 관리**: 판단마다 모델 ID, 프롬프트 버전, 입력 스냅샷, 출력을 기록한다. 프롬프트나 모델을 바꾸면 lab 버전을 올리고 앞으로 검증 기간을 처음부터 다시 센다.

**운영 범위**: 응답 지연과 비용 때문에 일봉·스윙(하루 1~몇 회 판단)부터 시작한다. 분 단위 단타에는 쓰지 않는다.

**LLM 판단의 내부 구성** (TradingAgents에서 흡수)
- 애널리스트 분업: 기술·펀더멘털·뉴스·국면 담당이 각자 짧은 의견을 낸 뒤, 판단 담당이 종합한다.
- 강세/약세 토론: 결론 전에 반대 논거를 반드시 한 번 작성시킨다.
- 모델 분리: 애널리스트는 빠르고 싼 모델, 최종 판단은 깊은 모델 (비용 통제).
- 현재 보유 포지션을 입력에 포함한다 (보유 상태를 모르는 관점은 쓸 수 없음).
- 판단은 전부 `llm/decision_log.py`에 남기고, 보유 기간이 지나면 판단 후 첫 종가 진입 기준으로 채점한다 (벤치마크 대비 alpha 포함). 이 표가 앞으로 검증의 기록이다.

## 8. 에이전트 구성

LLM 에이전트는 **판단·해석·검토**만 맡고, 숫자 계산과 주문 경로는 Python 코드가 맡는다.
총괄은 대화 중인 Claude(메인 세션)이며, 아래 에이전트에게 일을 나눠 맡긴다. 인수인계는 대화가 아니라 파일로 한다.

| 에이전트 | 팀 | 하는 일 | 입력 → 출력 | 권한 | 모델 | 실행 |
|---|---|---|---|---|---|---|

| `quant-researcher` | ② 리서치 | 가설 작성, 전략 코드, 백테스트 실행, 결과 정리 | 아이디어 → `labs/L###/` | `labs/` 쓰기 | 깊은 모델 | 대화 중 |

**에이전트가 아닌 것 (코드)**: 수집, 국면 지표 계산, 상태 점검, 백테스트 엔진, 운용데스크, 리스크(거부권), 주문 실행, 잔고 대사.

**구현 형태**
- 대화 중 역할(`quant-researcher`, `validator`)은 Claude Code 서브에이전트(`.claude/agents/*.md`)로 만든다.
- 정해진 시각에 혼자 도는 역할(`market-analyst`, `ops-reporter`, `llm-desk`)은 **Claude Code CLI(`claude -p`)** 로 돌린다 (2026-11-15 결정: 구독 안에서, 추가 과금 없음).
  `llm/claude_cli.py`가 도구 없이(`--tools ""`), 세션을 남기지 않고 호출하며, `--json-schema`로 구조화 출력도 받는다. 실패하면 None → 해당 기능만 빠지고 나머지는 그대로 돈다.
- 모든 LLM 호출은 모델·프롬프트 해시·소요 시간·성공 여부를 `logs/llm_calls.jsonl`에 기록한다 (7절 버전 관리).
- 서브에이전트 정의: `.claude/agents/{validator,quant-researcher,market-analyst,ops-reporter}.md`. validator의 "전략 코드 수정 불가"는 도구 목록(Write·Edit 없음)과 지침으로 막는다.
