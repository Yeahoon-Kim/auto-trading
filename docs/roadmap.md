# 로드맵

> 조직 구조(시장정보·리서치·검증·운용·리스크·운영)와 LLM 사용 원칙은 [architecture.md](architecture.md) 참고.
> 아래 Step 1~3은 그 조직이 만들어지는 순서다: Step 1 = 운영팀 수집, Step 2 = 리서치·검증팀, Step 3 = 운용·리스크팀.

```
[1. 데이터 파이프라인] ──▶ [2. Labs: 시장 선택 → 전략 → 백테스트 → 검증]
                                          │ validated 판정을 받은 것만
                                          ▼
                          [3. 실행 모드: paper(모의) ──▶ live(실전, 단계적 증액)]
```

원칙: 무료 데이터만 사용하고, 초장기 투자가 아닌 중단기·단타·차익거래를 중심에 둔다.

## Step 1 — 데이터 수집 파이프라인
과거 데이터를 한 번에 받아 두고(백필), 이후에는 정해진 주기로 갱신한다.

| 시장 | 일봉 | 분봉 | 기타 | 무료 소스 (후보) |
|---|---|---|---|---|
| KR 주식 | 장기 백필 가능 | 과거 이력 제한적 → **지금부터 직접 쌓아야 함** | 재무(DART), 상장폐지 종목 | pykrx, FinanceDataReader, KIS API, OpenDART |
| US 주식 | 장기 백필 가능 | 1분봉 최근 7일, 5분봉 최근 60일 수준 → 직접 쌓아야 함 | 재무 일부 | yfinance, KIS 해외 API |
| 코인 현물·선물 | 장기 백필 가능 | 장기 백필 가능 | 펀딩비, 미결제약정, 호가 | data.binance.vision (대량 히스토리), Binance API |
| 국내 거래소 코인 | 가능 | 가능 | 김치 프리미엄 계산용 | Upbit API |

- 저장: parquet (시장/타임프레임/심볼별로 분할) + duckdb 쿼리
- **가격은 원본 + 조정계수로 저장**하고, 수정주가는 불러올 때 계산한다 (조정계수는 새 분할·배당이 생기면 과거분까지 바뀌기 때문).
- **재무 데이터는 공시일 기준**으로 붙인다 (미래참조 방지).
- **스냅샷**: lab 실행 시 데이터 스냅샷 ID를 기록해 결과를 재현할 수 있게 한다.
- **수집 상태 기록**: 수집 작업별로 마지막으로 받은 시점을 저장하고, 재시작하면 비어 있는 구간부터 이어서 받는다.
- 갱신: 스케줄러 (처음에는 로컬, 이후 Oracle 서버)
- 품질 점검: 결측, 시간대(KST/UTC) 통일, 중복 제거
- KIS는 기존 실전 키를 **조회 전용 REST API**로만 사용한다 (호출 한도 이중화는 나중에 검토).

## Step 2 — Labs
`labs/README.md` 참고. 원칙: 가설 먼저 기록, 워크포워드 검증, 고정 통과 기준, 최근 6개월 잠금 구간은 판정 시 1회만 확인.
전략 코드는 하나의 프레임워크로 작성해서 백테스트·paper·live에서 그대로 쓴다. 바뀌는 것은 데이터 공급과 주문 체결 모듈뿐이다.

후보 아이디어:

- **고전 기법**: 다모다란 상대가치(PER/PBR/EV-EBITDA), 그린블라트 마법공식, 피오트로스키 F-Score, 모멘텀(12-1), 저변동성 — 중기(월 단위) 리밸런싱으로 검증
- **단타·알고리즘**: 변동성 돌파, ORB(장 초반 범위 돌파), VWAP 회귀/추세, 갭 트레이딩, 평균회귀, 호가 불균형(코인), ML 단기 예측
- **차익거래**: 현물-선물 베이시스, 펀딩비 차익, 김치 프리미엄(Upbit↔Binance), 삼각 차익, 페어트레이딩(공적분)

## Step 3 — 실행 모드
- **paper**: KR/US는 KIS 모의투자 API(키는 추후 발급 예정), 코인은 Binance 테스트넷. 차익거래처럼 테스트넷이 없는 경우에는 실시간 시세로 가상 체결하는 시뮬레이터를 사용
  - 구현 (2026-11-15): `uv run python -m autotrader.runner.paper labs/L###-이름` — 수집이 끝난 뒤 하루 한 번.
    같은 `generate_signals()`로 목표 비중 → risk.yaml 한도 → 종가 기준 수량의 지정가 주문(±`paper.limit_band_pct`, 기본 5%)
    → 다음 봉 시가에 가상 체결. 기록은 `results/paper/<lab>/` (book.json·events.jsonl·equity.csv), 요약은 텔레그램.
    `--replay-days N`은 최근 N봉을 새 계좌로 재생해 엔진과 비교한다 (한도를 끄면 엔진과 같은 조건).
  - 지원: kr_stock, crypto_spot(`lab.yaml`에 `paper.krw_per_unit` 필요), 롱만, rebalance `always`·`on_signal`.
  - 엔진과 다른 점: 수량을 주문 시점(전날 종가)에 정한다(엔진은 체결 봉 시가) · 지정가 밖이면 취소 ·
    상장폐지를 미리 모르므로 시세가 3회 연속 없으면 마지막 가격에 정리 · 분할·병합은 원본가/수정주가 수익 차이로 수량 조정.
    합성 데이터 1년 최대 차이 0.18%, L001 실데이터 250봉(한도 끔) 최대 1.7%.
  - risk.yaml 한도가 전략 규칙보다 우선한다. 예: `max_open_positions: 10`이면 20종목 전략은 10종목만 산다 (이벤트로 기록).
- **live**: `config/risk.yaml`의 `live_gate`를 통과한 전략만 소액으로 시작하고, 성과가 유지되면 단계적으로 증액
- **퇴출**: 전략마다 `lab.yaml`의 `retirement` 조건으로 감시한다. 전략 간 상관관계와 포트폴리오 배분은 현재 범위가 아니다.
- 운영 환경: 시나리오별로 로컬 PC, Docker, Oracle Cloud 무료 서버를 선택 (`deploy/`)
- 모니터링: 텔레그램 알림, 매매 일지(`docs/journal/`)
